**Decisions argued here**

| Decision | Rationale in one line |
|---|---|
| Fixed bottom-right FAB on all pages | v1 has no per-page context awareness |
| `useChat` owns panel state | The SDK already has the client state machine |
| Refusals render as a distinct block, not an error | Refusal is intended behavior |
| Sign-in interstitial inline, pending question replayed | The gate should not lose the question |
| Three starter chips, none of them a refusal | Refusal is good to encounter, not to advertise on arrival |
| Chips verified against the eval set before shipping | They are the only questions guaranteed to be asked |

---

Fixed bottom-right FAB, all pages. `useChat` owns panel state.

- Collapsed: circular button, cyan accent (`#00d9ff`), `aria-label="Ask about Tanish's work"`.
- Expanded: ~380px panel, max 70vh, bottom sheet on mobile.
- Answer area, sources as citation pills linking to `route` or `external_url`.
- Trace toggle reads transient parts via `onData`. See [05 Runtime](05-runtime.md).
- Refusals render as a distinct block, not an error.
- Sign-in interstitial appears inline before the second generated answer, with the pending
  question held and replayed. See [07 Identity and the gate](07-identity-gate.md).
- Respects `prefers-reduced-motion`. Focus trap, Esc closes, WCAG AA contrast.

## Starter chips

1. "What broke while building ESMON?" (where the colleague voice separates from a publicist).
   Grounded in `project-esmon.md`: the PDF threading deadlock and the filter-context rewrite both
   read as failures first, fixes second. `philosophy.md` corroborates with a paragraph retelling
   the same filter bug under "Interfaces as contracts," but that is one paragraph against a whole
   document; most of the weight sits on `project-esmon.md` alone. Worth a specific check against
   the eval set before shipping, since this is the chip with the thinnest second source.
2. "How does Noiseless keep a human in the loop?": factual, strongly grounded.
   `project-discovery-agent.md` carries the dedicated section ("Human in the loop as the
   foundation"). `philosophy.md` restates the same claim twice, under "AI as substrate, not
   feature" and "Interfaces as contracts." `identity.md` states it again under "What he builds."
   Three distinct documents converge on one claim; this is the best-grounded of the three.
3. "What's he like to work with?": personal, not project-shaped. `personal.md` answers it
   directly, in "Why any of this is in the corpus." `identity.md` corroborates from "Positioning"
   (generalist by circumstance, comfortable owning a system end to end without a designer or a
   senior engineer). `philosophy.md` corroborates again from "How he works" (trusts a working
   version over a plan, built mostly without anyone senior to check against). Three documents, one
   consistent claim.

**Every chip is verified against the eval set before shipping.** They are the only questions
guaranteed to be asked, so a chip regression is a launch blocker. No refusal chip: refusal is good
to encounter, not to advertise on arrival. No HybridFit chip either: HybridFit is not a priority
project and does not get the free visibility of a chip a visitor sees on arrival. `code-hybrid-fit.md`
stays in the corpus for visitors who ask about it directly; it just does not back a starter chip.
